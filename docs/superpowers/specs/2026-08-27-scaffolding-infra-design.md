# Scaffolding and local infra

Date: 2026-08-27

Status: approved in conversation; waiting on file review before the implementation plan.

This spec is the foundation pass only: repo tree, local Postgres (Supabase CLI), local object storage (MinIO), empty Next.js and .NET shells, schema, and the contracts those shells must obey. Catalog UI, player, install form, terms page, real blob writes, and analytics behavior are out of scope here.

Product intent and table meanings stay in `docs/proposal.md`, `docs/phase-1/requirements.md`, `docs/phase-1/design-doc.md`, `docs/phase-1/db-design.md`, and `docs/phase-1/cli-design.db`. This file does not replace those. It records scaffolding decisions made on top of them.

## Goal

Stand up a bootable tree under `/home/lbantoli/Desktop/projects/personal-music-store` so later work can fill in features without re-litigating layout or hosts.

When this pass is done:

- Local Postgres is running via `supabase start` and has the three tables from `db-design.md`.
- MinIO is running via Docker Compose and speaks S3.
- `next dev` serves a blank store page.
- The admin upload route rejects requests without the shared secret (`401`).
- `dotnet build` succeeds and the CLI prints help.

No cloud Supabase project and no Backblaze account are required for this pass.

## Locked decisions

| Topic | Choice |
| --- | --- |
| Next.js location | `app/` (project root for the store) |
| CLI location | `app/cli/` |
| Next.js routes | App Router under `app/src/app` so we do not nest `app/app/` |
| Schema host | Supabase (Postgres). Cloud later; local stack now |
| Schema ownership | SQL migrations in git via Supabase CLI |
| Next.js data access | Server-only. Browser never uses the anon key for catalog or downloads |
| CLI data access | Npgsql against the Postgres connection string |
| Object storage now | MinIO (S3 API) |
| Object storage later | Backblaze, same AWS SDK, env swap |
| Blob owner | Next.js. CLI POSTs the file; server returns two URLs; CLI inserts `playable_audio` |
| Stream vs download | Same bytes, two objects. No transcode in phase 1 |
| Public auth | None. Store is public |
| Admin protection | Shared secret header on the upload route |

## Stack pins (scaffold)

- Next.js (current App Router), TypeScript, `src/` directory, npm.
- Server SQL: `postgres` (postgres.js) with parameterized SQL. Migrations stay in `supabase/migrations/` only. Do not introduce a second migrator (no Prisma migrate, no Drizzle migrate).
- S3: AWS SDK v3 (`@aws-sdk/client-s3`), path-style addressing for MinIO.
- CLI: .NET 8, `System.CommandLine`, Npgsql.

## Local infra

### Postgres

- `supabase start` for day-to-day.
- Schema only from `supabase/migrations/`.
- A free cloud project is later: same migration files, new connection string.
- Next.js and the CLI both use the Postgres URI printed by `supabase start` as `DATABASE_URL` (direct protocol, not PostgREST).

### MinIO

- One Compose service, one bucket.
- API on `127.0.0.1:9000`, console on `127.0.0.1:9001`.
- Two key prefixes: `stream/` (public-read for keys under that prefix) and `download/` (private).
- Default local credentials live in env examples, never in git as real secrets.

Prod later: same SDK, `S3_ENDPOINT` / keys / bucket pointed at Backblaze B2’s S3 API. No code fork for “MinIO vs Backblaze” beyond env.

### Env (not committed)

Next.js (`app/.env.local`):

- `DATABASE_URL`
- `ADMIN_SECRET`
- `S3_ENDPOINT` (e.g. `http://127.0.0.1:9000`)
- `S3_REGION` (MinIO accepts a dummy region such as `us-east-1`)
- `S3_ACCESS_KEY`
- `S3_SECRET_KEY`
- `S3_BUCKET`
- `S3_FORCE_PATH_STYLE=true`

CLI (`app/cli/.env`, gitignored, loaded locally):

- `DATABASE_URL` (same local Postgres)
- `UPLOAD_API_URL` (e.g. `http://127.0.0.1:3000/api/admin/upload`)
- `ADMIN_SECRET` (same value as the server)

Commit `.env.example` files with empty or dummy placeholders. Gitignore real env files.

## Schema (migration 1)

SQL types for the three tables. Meanings stay in `docs/phase-1/db-design.md`.

Shared conventions:

- `id integer generated by default as identity primary key`
- `created_at timestamptz not null default now()`
- `updated_at timestamptz not null default now()`
- Application code sets `updated_at` on write; no trigger required in this pass

### playable_audio

- `title text not null`
- `published boolean not null default false`
- `stream_blob_url text not null`
- `download_blob_url text not null`

### contacts

- `email text not null unique` (case-sensitive at the DB; later writes should store lowercase)
- `name text null`
- `role text null` with `check (role is null or role in ('producer', 'artist', 'other'))`
- `instagram text null`
- `x_handle text null`

### installs

- `contact_id integer not null references contacts(id) on delete restrict`
- `playable_audio_id integer not null references playable_audio(id) on delete cascade`
- `count integer not null default 1 check (count >= 1)`
- `unique (contact_id, playable_audio_id)`

Deleting a track removes its install rows. Contacts are not deleted in this pass (`on delete restrict`).

Terms and conditions are not tables. They are app copy later.

No seed data.

## Module shells

### Next.js

- Placeholder route at `/` so the app boots.
- `src/lib/db.ts`: server-only client from `DATABASE_URL`. Unused by UI in this pass except possibly a future health check.
- `src/lib/s3.ts`: server-only S3 client from env. Unused by the stub besides existing.
- `POST /api/admin/upload`:
  - Header: `X-Admin-Secret` must equal `ADMIN_SECRET`.
  - Missing or wrong secret → `401` with a short JSON error. No stack traces.
  - Valid secret, this pass → `501` and a short JSON body (`not implemented`). No object writes, no DB writes.
- Do not expose `download_blob_url` to any public route (none exist yet besides `/`).

### CLI

Commands (help text now; behavior later except as noted):

- Create playable audio: `--file` / `-f` (path), `--title` / `-t` (string), `--published` / `-p` (`true` or `false`)
- Read / update / delete playable audio
- Analytics

This pass:

- `dotnet run -- --help` lists those commands.
- Create parses flags. If invoked, it POSTs the file to `UPLOAD_API_URL` with `X-Admin-Secret`. On `501` it prints the server message and does **not** insert. On `401` it prints that the secret failed. It does not call Npgsql until implementation.
- Other commands print `not implemented` and exit non-zero.

### Upload contract (implementation, not this pass)

Documented now so the stub URL and CLI flags stay stable:

1. CLI POSTs `multipart/form-data` fields `file` (the audio), `title` (string), `published` (`true` or `false`) with `X-Admin-Secret`.
2. Server writes two objects (same bytes): `stream/<id-or-key>` and `download/<id-or-key>`.
3. Server returns JSON `{ stream_blob_url, download_blob_url }`.
4. CLI inserts `playable_audio` via Npgsql.

If S3 fails, CLI must not insert. If insert fails after S3 succeeded, leftover objects are acceptable in phase 1 (no distributed rollback).

## Error contract

| Case | Response |
| --- | --- |
| Missing/wrong admin secret | HTTP `401` |
| Missing file or title (later) | HTTP `400` |
| MinIO/S3 down (later) | HTTP `503`; CLI does not insert |
| DB insert fails after blobs (later) | CLI error; orphans allowed |
| Unimplemented stub with valid secret | HTTP `501` |

CLI prints a short message. Public responses never include stack traces.

## Security (this pass)

- Store is public. No user auth.
- Upload is the only privileged route. Shared secret is enough for a solo admin.
- Service role / DB URL never shipped to the browser.
- MinIO and Supabase ports bound for local use, not advertised as production.

Signed download URLs and Backblaze key rules belong to a later spec.
